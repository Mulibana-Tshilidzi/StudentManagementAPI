# StudentManagementAPI
## About This Project
Student Management REST API built with ASP .NET Core
## Setup Instructions
Open the solution in Visual Srudio
Run the project 
Test endpoints via Swagger
## API Endpoints
-GET / api/ students - Get all students
-GET / api/ students/{id} - Get student by ID
-POST / api/ students - Create new student
-PUT / api/ students/{id} - Update student
-DELETE / api/students/{id} -Remove student
## HTTP Status Codes
- 200 OK — Request successful
- 201 Created — New record added
- 404 Not Found — Student does not exist
## Student Model Properties
- Id — Unique identifier
- Name — Student first name
- Surname — Student last name
- Email — Student email address
- Course — Academic course enrolled
- Year — Current study year
- PhoneNumber — Contact number (custom property)
PhoneNumber is included as the additional custom property
for direct contact communication.
## GET All Students
- Returns the full list of all students in the system
- No parameters required
- Returns 200 OK on success
## GET Single Student by ID
- Accepts an integer ID in the URL
- Returns 200 OK if found
- Returns 404 Not Found if no student matches the ID
## POST Create Student
- Accepts student details in JSON body
- ID is automatically generated by the system
- Returns 201 Created with the new student data
## PUT Update Student
- Accepts student ID and updated details
- Returns 200 OK when updated successfully
- Returns 404 Not Found if student does not exist
## DELETE Remove Student
- Accepts student ID to be removed
- Returns 200 OK when deleted successfully
- Returns 404 Not Found if student does not exist
## Error Handling
All endpoints return 404 Not Found when an operation
targets a student ID that does not exist in the system.

## MVC vs API Controllers
- MVC Controllers return views for the user interface
- API Controllers return structured data (JSON)
- Both can coexist in the same ASP.NET Core application
## REST API Principles
- Stateless — Each request contains all information needed
- Uniform Interface — Consistent naming and methods
- Resource-Based — Uses URLs to identify data resources
